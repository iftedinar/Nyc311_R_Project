# NYC 311 Service Request Analytics

An R-based exploratory study of recorded closure times and unusually slow cases in a supplied NYC 311 service-request sample. The project investigates closure-time distributions, variation by request characteristics, and the limitations of linear and logistic prediction models.

## Scope and interpretation

The supplied sample contains 40,000 rows, of which 39,668 have usable closure durations. Every supplied record is marked Closed. This is not a representative sample of all incoming NYC 311 requests, and recorded closure does not establish that the underlying issue was resolved. The logistic model's discrimination was weak (validation AUC approximately 0.554); the work is exploratory and is not a deployed decision system.

## Repository contents

- `NYC311_Analysis.R` — main R analysis, using base R.
- `Nyc311_R_Project.Rproj` — RStudio project file.
- `LinkedIn_NYC311_Scholarly_Article.md` — accessible summary of methods, findings, and limitations.
- `analysis/figures/` — figures generated by the R analysis.
- `analysis/tables/` — aggregate descriptive statistics, model metrics, and results.
- `analysis/verify_results.R` — independent checks of saved validation metrics.
- `analysis/question_code/` — optional question-by-question companion scripts; these require the main analysis to have run first.
- `analysis/sessionInfo.txt` — recorded R environment.

The repository intentionally omits classroom submission files, private working files, RStudio caches, and row-level datasets pending a source, privacy, and redistribution review.

## Reproducing the analysis

1. Install R and optionally RStudio. The project was originally run with R 4.6.1 and base R; check `analysis/sessionInfo.txt` for the saved environment.
2. Obtain the original `NYC311_April2025_RawSample.csv` through an authorized source. Place it in the project root beside `NYC311_Analysis.R`. **The exact numerical outputs cannot be reproduced without the same supplied sample.**
3. Open `Nyc311_R_Project.Rproj`, or set the R working directory to the project root.
4. Run:

   ```r
   source("NYC311_Analysis.R", echo = TRUE)
   ```

   This regenerates the outputs under `analysis/`, including tables and figures. It can overwrite previously generated outputs.
5. To run the independent saved-metric checks:

   ```r
   source("analysis/verify_results.R")
   ```

6. Optional question-specific scripts in `analysis/question_code/` require objects created by the main analysis. `analysis/run_question_code.R` can run the companion examples.

## Key methodological cautions

- Closure time is calculated from available creation and closure timestamps; it is not a verified service-quality outcome.
- The analysis includes only closed requests in the supplied sample, so selection bias limits generalization.
- The linear model's reported RMSE of approximately 1.3089 is in `log(1 + hours)` units, not hours.
- At the default 0.50 logistic cutoff, the model identifies no positive slow cases in the saved validation results; accuracy alone is misleading.
- The 0.25 cutoff is an exploratory screening assumption, not a validated operational decision threshold.
- Observed borough differences do not establish causal effects or service discrimination.
